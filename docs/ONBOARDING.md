# 让用户少操作：本机发现与连接器

状态：**产品方向，尚未实现一键启动器或自动配对。** 当前静态预览用于审查已有工作台；开发版仍采用配置文件、独立服务和独立连接器。

## 连接器究竟是什么

它是一个运行在 Java 进程所在电脑上的小程序。网页负责展示，连接器负责扫描进程、执行 Attach、读取目标 Arthas 响应。团队模式下，它还会主动连接中心服务器，把这台电脑上的授权实例接入共享工作台。

不需要用户为了使用这个程序理解 WebSocket、端口转发或 MCP 会话。连接器是实现方式，产品里可以叫“本机助手”，并作为启动器内置组件运行。

浏览器不会因为网页来自本公司或部署在局域网就获得操作系统进程访问权限。文件选择、Chrome 扩展、PWA 也不会自动授予完整进程扫描和 JVM Attach 能力；扩展若要实现它们，仍需要本机原生组件。JDK 的 `jps`/Attach API 同样必须在能访问目标进程的机器和权限上下文中执行。

## 推荐的两种使用方式

### 个人本机模式：一次启动

目标体验：

1. 用户下载一个启动器。
2. 双击后，启动器拉起本机服务并自动打开浏览器。
3. 页面显示本机可见的 Java 进程，用户无需输入 URL、端口或令牌。
4. 用户选择进程并点“连接”，再使用本机 MCP 地址。

实现方向：启动器为自身生成随机凭证，通过一次性浏览器启动票据完成本机登录；票据短时有效，交换后从地址栏移除。服务默认只监听回环地址，并校验来源。凭证不能硬编码在前端或长期放在 URL 中。

进程发现可在页面进入或点击刷新时执行，后续采用低频、可取消刷新。进程身份需要在 Attach 前再次核对。**自动发现可以默认进行，自动 Attach 到所有进程不应默认进行。**

这是最适合首先打磨的低操作路径。不需要中心服务器，也不要求每位使用者先部署数据库。

### 团队共享模式：首次登录一次

目标体验：

1. 团队部署统一服务；K8s 由管理员配置一次。
2. 用户从工作台获取本机助手，首次启动通过浏览器登录/一次性配对绑定账户。
3. 助手主动连回团队服务器；网页自动显示“我的电脑”。
4. 后续启动自动重连，用户只需选择要诊断的进程。

K8s 的普通使用者只需要浏览器和权限，不必安装本机助手。只有要诊断自己电脑上的 JVM 时才需要本机组件。不要要求用户安装完再手填节点 ID、长令牌、服务器端口和多份 JSON。

可以提供系统托盘和可选开机启动，但应由用户开启；退出、暂停共享、撤销设备授权应当容易找到。工作站实例默认私有，分享给团队是显式动作。

## 方案比较

| 方案 | 首次操作 | 本机进程能力 | 建议 |
| --- | --- | --- | --- |
| 纯网页 | 打开网址 | 无法直接枚举或 Attach 本机 JVM | 适用于已由服务器接入的 K8s |
| 单个本机启动器 + 浏览器 | 下载、双击 | 通过内置原生组件获得 | 优先完善个人模式 |
| 团队 Web + 本机助手 | 下载、首次登录/配对 | 通过原生组件接入共享工作台 | 保留为团队模式 |
| IDE 插件 | 安装到每种 IDE | 可由插件/子进程扫描目标 | 后续便利入口，不能覆盖所有使用者 |
| 浏览器扩展 + 原生宿主 | 安装两个组件 | 仍依赖本机宿主 | 当前收益小于安装成本 |

## 当前代码与目标体验的差距

已有：本机扫描、显式 Attach、反向连接、统一实例路由、用户/节点令牌区分。

待实现：单文件/安装包交付、进程托管、首次启动引导、自动开浏览器、一次性登录票据、团队设备配对、设备撤销、自动更新、跨平台真实 JVM 验收。

技术上可以让多个进程由一个启动器托管，因此“内部有服务端和连接器”并不意味着用户必须开两个终端。实现这些体验前，不在 README 中宣传零配置或开箱即用安装包。
