# 团队共享工作台与本机助手

状态：**产品方向，尚未实现一键启动器、自动配对或中央资源分发。** 新设计原型使用纯模拟数据；可运行的双链路版本仍使用配置文件。团队共享服务器是产品主入口，不要求每位同事部署一份本机 Web 服务。

## K8s 用户路径

1. 管理员配置环境、集群访问范围、应用部署映射及执行节点。
2. 用户登录团队工作台，选择环境和应用。
3. 查看该应用的多个 Pod，选择具体 JVM 并发起诊断。
4. 系统按权限准备连接；已纳管目标由后台独立维护，浏览器只显示状态。

K8s 的普通使用者不需要安装本机助手。应用的工作节点是 Pod 的调度位置，与负责访问集群的 Connector 执行节点不是同一个概念。

## 本机 Java 用户路径

1. 用户从团队工作台获取助手，在需要诊断的电脑上运行一次。
2. 首次通过登录／一次性配对绑定账户和设备；后续启动自动连回团队服务器。
3. 网页显示“我的电脑”，点击扫描，由助手列出其权限范围内的 Java 进程。
4. 用户选择目标进程；助手核验身份，优先复用已有 Arthas，必要时准备资源并执行授权 Attach。
5. 通过相同的 Web 诊断界面或统一 MCP URL 使用该实例。

用户无需手工填写节点 ID、长令牌、多个端口与 JSON。首次配对的凭证交换、设备撤销、自动更新与跨平台打包仍需实现。工作站实例默认私有，分享给团队必须明确授权。托盘和开机启动可作为后续便利选项，不作为诊断的额外必经步骤。

## 中央资源管理

`arthas-bin.zip` 由服务器统一管理版本与校验信息，助手或集群执行节点按需下载、验证和缓存。K8s 文件传输沿用 Perl 管线方向，不引入 OBS。

资源下载不会绕过操作系统身份、目标 JVM 的 Attach 配置、容器命名空间或集群权限限制。资源版本与通道状态应分别展示；“已下载”不等于“已 Attach”，端口可达也不等于已验证目标身份。

新 Attach 默认 `telnetPort=-1`，通过 HTTP/MCP 诊断。此默认不会自动关闭旧实例已经运行的 Telnet 监听。

## 连接器的责任

浏览器受沙箱限制，不能直接枚举操作系统 Java 进程或执行 Attach。连接器运行在能访问目标的执行环境中，主动建立到中央服务器的连接，代为完成这些操作。浏览器扩展、PWA 或文件选择不会自动授予这些原生能力。

本机助手退出、电脑休眠或网络中断时，工作台应显示离线状态。正式的连接维护不依赖网页是否打开。当前设计原型中的重连只是浏览器内模拟，关闭页面即结束，不能用来证明后台监督已实现。

## 身份与任务

环境负责组织应用，诊断任务绑定具体 Pod/容器/JVM 身份。相同应用名跨环境不共享连接或任务。同名 Pod 重建后产生新实例身份；旧任务保留目标快照并明确中断，不自动重放到新 JVM。

用户可以一次对多个副本发起诊断，各实例生成独立任务。共享通道不意味着共享用户凭证或所有任务的操作权限。正在执行的任务不随导航环境切换而改变归属。
