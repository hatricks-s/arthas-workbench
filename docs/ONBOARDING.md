# 团队共享工作台与本机助手

状态：**产品方向，尚未实现一键启动器、自动配对或中央资源分发。** 新设计原型使用纯模拟数据；可运行的双链路版本仍使用配置文件。团队共享服务器是产品主入口，不要求每位同事部署一份本机 Web 服务。

## K8s 用户路径

1. 管理员登记集群及访问范围、绑定执行节点；首版一个集群对应一个环境。
2. 用户登录团队工作台，选择环境，默认查看该集群中的全部候选 Java 目标。
3. 按 Namespace、工作负载或 Node 筛选，选择一个或多个具体 JVM 发起诊断批次。应用不是必须配置或选择的入口。
4. 系统按授权范围准备连接；已纳管目标由后台独立维护，发现 Pod 不等于自动 Attach。浏览器只显示状态。

K8s 的普通使用者不需要安装本机助手。应用的工作节点是 Pod 的调度位置，与负责访问集群的 Connector 执行节点不是同一个概念。

## 本机 Java 用户路径

1. 用户从团队工作台获取助手，在需要诊断的电脑上运行一次。
2. 首次通过登录／一次性配对绑定账户和设备；后续启动自动连回团队服务器。
3. 网页将每台已配对设备列为独立的本机环境；选择设备后点击扫描，由对应助手列出其权限范围内的 Java 进程。离线设备保留上次清单，但不接受扫描或诊断。
4. 用户选择目标进程；助手核验身份，优先复用已有 Arthas，必要时准备资源并执行授权 Attach。
5. 通过相同的 Web 诊断界面或统一 MCP URL 使用该实例。

用户无需手工填写节点 ID、长令牌、多个端口与 JSON。首次配对的凭证交换、设备撤销、自动更新与跨平台打包仍需实现。工作站实例默认私有，分享给团队必须明确授权。托盘和开机启动可作为后续便利选项，不作为诊断的额外必经步骤。

## 中央资源管理

`arthas-bin.zip` 由服务器统一管理版本与校验信息，助手或集群执行节点按需下载、验证和缓存。K8s 文件传输沿用 Perl 管线方向，不引入 OBS。

资源下载不会绕过操作系统身份、目标 JVM 的 Attach 配置、容器命名空间或集群权限限制。资源版本与通道状态应分别展示；“已下载”不等于“已 Attach”，端口可达也不等于已验证目标身份。

新 Attach 默认 `telnetPort=-1`，通过 HTTP/MCP 诊断。此默认不会自动关闭旧实例已经运行的 Telnet 监听。

## 连接器的责任

浏览器受沙箱限制，不能直接枚举操作系统 Java 进程或执行 Attach。连接器运行在能访问目标的执行环境中，主动建立到中央服务器的连接，代为完成这些操作。浏览器扩展、PWA 或文件选择不会自动授予这些原生能力。

本机助手退出、电脑休眠或网络中断时，工作台应显示离线状态。正式的连接维护不依赖网页是否打开。当前设计原型中的重连只是浏览器内模拟，关闭页面即结束，不能用来证明后台监督已实现。

## 身份与任务

环境代表一个集群或一台设备，诊断任务绑定具体 Pod/容器/JVM 身份。同名工作负载在不同 Namespace 或环境中分别识别；工作负载归属应追溯 Kubernetes ownerReferences，不能只猜 Pod 名称前缀。完成的初始化容器不作为 JVM 目标。同名 Pod 重建后产生新实例身份，旧任务保留快照并明确中断，不自动重放到新 JVM。

Web 与 MCP 共用诊断批次和独立子任务：一次提交固定目标与参数，按并发上限执行，支持独立取消、取消剩余、部分完成及结果对比。各目标保留自己的采样时间，不宣称严格同步采样。外部 AI 客户端负责分析推理，首版不内置聊天窗口。正在执行的任务不随导航切换而改变归属。

首版暂缓完整 RBAC 和组织架构，保留最小认证、凭证撤销、明确接入范围、能力开关和操作记录。共享通道不意味着共享用户凭证或任意操作其他人的任务。

## 当前差距

已有运行能力：本机扫描、显式本机 Attach、反向连接、统一实例路由、独立用户／节点凭证、流式传输及进程清理。

待实现：安装包与单程序交付、首次配对、资源分发、动态集群／目标发现、强 JVM 身份核验、已有 Arthas 可靠复用、K8s 上传与 Attach、独立目标后台监督、MySQL、Web/MCP 共用批次服务、持久任务与审计。当前运行版 MCP 诊断调用尚未进入 Web 任务记录；设计原型中的批次联动不代表该后端差距已补齐。

独立个人模式可以作为后续扩展，不再作为团队版第一阶段的主路径。
