# Diagnostics Workbench Prototype

`ui-prototype/`（由 `scripts/build_preview.py` 同步到 `docs/preview/`）是一个完全离线运行的交互原型。所有集群、工作负载与耗时数据来自前端确定性模型，页面禁止任何网络请求（`connect-src 'none'`）。

## 设计原则

一屏只做一件事，并且默认只呈现当前任务需要的信息：

- **一个视觉体系。** 全站浅色（`#f5f6f8` 画布 / 白色面板 / 单一强调色），唯一的深色表面只用于线程栈这类代码证据。
- **一条主行动线。** 默认顶栏只有环境与搜索；勾选目标后，同一位置原位切换为「已选 N 个 · 工具 · 参数 · 执行」。
- **信息分层。** 分组头承载工作负载名与 Namespace，行内只保留副本标识、状态与一个关键数字；完整名称、UID、容器与 PID 在详情弹层中查看（双击行）。
- **无边框分区。** 分区依靠留白、字号与分隔线，而不是层层卡片和描边。

## 页面

1. **总览**：一行一个环境（集群或已配对设备），显示节点数、Java 目标、已注入、MCP 可用、异常数与最后探测时间。点击进入该环境。
2. **集群**：以节点表为主视图。每个节点显示 Pod 数、已注入、MCP 可用、Namespace 聚合与探测时间；展开后按 Namespace 汇总，点击可直接进入该 Namespace 的目标列表。排序为“问题优先”，异常节点在前。
3. **诊断台**：左侧目标列表（按工作负载分组），右侧为当前批次的证据。批次内按副本并排列出，自动标出偏离基线的副本，下方为该副本的调用链火焰行、线程栈或内存分代。
4. **批次**：Web 与 MCP 共用同一份批次记录，右侧复用同一套证据视图。
5. **链路**：说明服务端的通道、按需注入、身份固定与本机接入方式，并给出 MCP 客户端配置。

每个目标带一条四段探测链：`通道 → 进程 → 注入 → MCP`。节点与总览的数字是这条链的聚合；“已注入”多于“MCP 可用”时，差值就是注入成功但端点不可用的目标，展开节点即可定位。

`Ctrl+K` / `⌘K` 打开命令面板。窄屏下列表与证据拆成两级，点击目标进入证据，顶栏提供「返回列表」。

## 交互约束

- 勾选目标到执行是唯一的主路径；未注入的目标在同一次操作中完成注入（通道握手 → 下发运行时 → 注入并执行），无需先手动连接。
- 一次批次只属于同一环境；执行前冻结目标快照（集群、Namespace、Pod UID、容器、JVM 身份）。
- Pod 重建或超时后任务标记中断，不在新实例上重放，也不把缺失结果记为 0。
- 发现目标不等于已挂载；探针状态与就绪计数分开呈现。

## 验证

```sh
python -B scripts/build_preview.py
node --check ui-prototype/model.js
node --check ui-prototype/app.js
node scripts/check_preview.mjs
```

八项契约测试在无 DOM、无网络、无定时器、无随机数的 VM 中运行，覆盖环境隔离、不可变快照、按需注入、并发与取消、重建不重放、离线设备等。
