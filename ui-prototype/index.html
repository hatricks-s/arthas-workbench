目标接入链路

浏览器只负责选择与查看。连接、注入与执行由服务器侧的 K8s 通道完成。

  1. K8s WebSocket 通道

    服务端用 v4.channel.k8s.io 直接复用 APIServer 连接，不再为每个目标启动 kubectl port-forward 进程，也不占用本地端口。

  2. 按需注入

    发现目标不等于已挂载。执行诊断时才下发精简包并调用 jattach，不启动第二个 JVM；/tmp 已有同版本包则直接复用。

  3. 身份固定

    执行前确认 Pod UID、容器与真实 Java PID（容器内通常不是 1 号进程）。Pod 重建后旧任务中断，不会在新实例上重放。

  4. 本机开发机

    同事电脑通过一次配对建立反向连接，扫描本机 JVM 无需配置 JAVA_HOME。
